# D2 · Connections, keys and outside services

Review of every API contract and every connection in the v2 shared documents: internal endpoints, outside services, keys and variables, hosts, ports, timeouts, fallbacks, health checks, installs and the browser-to-server boundary. Read on Oct 24, 2026, from 2:20 to 2:50 PM PT. This file is the only one the D2 reviewer wrote.

**Verdict: incomplete.** 2 blockers, 14 majors, 20 minors.

## Summary

The endpoint contracts hold up. Every route a plan serves or calls is in `docs/v2/contracts.md` section 5 or 11. The 13 variable names agree across section 1, `.env.example`, I2-core and the plans. The per-key timeouts line up from server budget to adapter abort to registry: 19 s, 19.5 s and 20 s for B14, and 58 s, 59.5 s and 60 s for B15. In scripted mode the browser makes no request beyond localhost.

What's missing is mostly how the cloud build really connects:
- On the cloud environment's default network level, Trusted, `npm ci` and the Playwright browser download fail, so V0 can't finish. The runbook says to carry on, but nothing can (finding 1).
- The cloud GitHub proxy refuses tag pushes, and every gate pushes `main --follow-tags` (finding 2).
- Nothing tells Gordon which accounts, keys and network secrets to set up. `docs/v2/apis-and-accounts.md` still doesn't exist (finding 3).
- The background servers and the trained model don't survive the cloud VM's limits, and nothing brings the model to the Windows demo machines (findings 4 and 5).
- The command guard, the G6 secrets scan and the demo harness know only the v1 keys (findings 6 and 7).
- Six contract holes would fail a gate: B08's owner screen, the I2-core self-test, the V0 key reading, the Agent Builder agent, the cold model and B14's listing budget (findings 8 to 13).

### Cloud facts I checked

From the Claude Code docs (Sources, at the end) and this planning session's own VM, which runs in the `cloud_default` environment that the build session most likely shares:
- Network levels are None, Trusted, Full and Custom. Trusted is the default. A level change reaches running sessions within about a minute.
- The Trusted list has npm, PyPI, crates.io, `static.rust-lang.org` and GitHub's release asset hosts. It has none of section 1's hosts: not `cdn.sheetjs.com`, `download.pytorch.org`, Hugging Face, the Playwright CDNs, SpacetimeDB, Elastic, Apify or Nessie.
- A changed variable reaches a running session only when its VM is next restored or rebuilt. A process started earlier keeps the old values.
- A network secret adds a header to requests for the hosts it lists, and those hosts become reachable even when the level wouldn't allow them. `api.anthropic.com` and the public package registries never get a secret.
- The GitHub proxy "rejects branch deletions and pushes of anything other than a branch, such as a tag".
- A VM pauses after a few idle minutes. A reclaimed VM gets back the conversation, not running commands. The Bash tool stops a background command at its time limit, 30 minutes by default and 2 hours at most. Commands that a foreground subagent starts stop when it finishes, so servers belong to the main session, as the runbook already says.
- In this VM, `HTTPS_PROXY` is a local agent proxy that re-terminates TLS. `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`, `PIP_CERT`, `CURL_CA_BUNDLE` and `CARGO_HTTP_CAINFO` point at its bundle, so httpx, requests, pip, npm and curl work through it. `NO_PROXY` covers `localhost`, `127.0.0.1`, `::1`, `api.anthropic.com`, the npm registry and PyPI. The proxy doesn't carry WebSocket upgrades. `NODE_USE_ENV_PROXY` is unset, so Node's built-in `fetch` ignores the proxy. No Node script in the plans fetches an outside host, which is right.
- `ANTHROPIC_BASE_URL` is set, to `https://api.anthropic.com`. `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers` holds Chromium build 1194, and `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` is set. Node is 22.22 and Python 3.13.

## 5. The browser boundary

- Every adapter fetches relative `/api/...` paths, which Vite's dev and preview servers proxy to port 8000. OK.
- In scripted mode the registry calls no `health()` and starts no adapter, and `useSourceHealth` polls only in live mode. B13's `EventSource` and B15's background scan start only from `start()`, in live mode. OK.
- Fonts come from Fontsource packages. Piece illustrations come from `public/images/`, and `npm run art -- --check` rejects outside references. The model stays on the server, and map points arrive inside `search.mapped`. OK.
- F-watch never links to, frames or loads an image from a found URL, and scripted URLs are on `example.com` and `example.org`. F-process shows `hubUrl` only as a link. OK.
- B08's owner screen fetches only `/api/b08/...`. OK.
- `test:offline` aborts every request beyond localhost, but `context.route` doesn't see WebSockets (34).
